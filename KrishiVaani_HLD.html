Architecture Status & Baseline Scope Declaration

Official Engineering Disclosure: This High-Level Design (HLD) document defines the target production-grade, distributed microservices architecture for the KrishiVaani enterprise ecosystem. The design decouples web presentation (React/Vite + Tailwind CSS), API orchestration and gateway security (Node.js + Express.js), low-latency analytical model serving (Python FastAPI with Scikit-learn and PyTorch/CNN), domain retrieval-augmented generation (FAISS Vector Index + LangChain RAG pipeline), and scalable multi-tenant document persistence (MongoDB Atlas). External integrations include Sarvam AI (Indian language Speech-to-Text, Neural TTS, and Mayura translation), OpenWeatherMap, and Cloudinary. Components currently operating in single-node prototypes are clearly highlighted alongside their migration path to this production baseline.

01

Executive Summary

KrishiVaani (कृषिवाणी) is an enterprise-grade, AI-powered agricultural intelligence platform designed to empower smallholder and commercial farmers across Bharat with scientific, data-driven farming decisions. Operating at the intersection of precision agriculture, predictive machine learning, edge computer vision, and generative AI, KrishiVaani delivers personalized agronomic guidance spanning the entire agricultural lifecycle—from pre-sowing soil evaluation to harvest yield optimization and plant disease containment.

The platform addresses structural inefficiencies in Indian agriculture where over 140 million farmers face declining soil fertility, extreme weather shocks, pest invasions, and unpredictable market realizations. By consolidating distributed agronomic intelligence into an intuitive, voice-enabled web and mobile interface, KrishiVaani bridges the severe digital and linguistic divide prevalent in rural agricultural ecosystems.

Target Demographic
Marginal & Smallholder Farmers

Over 86% of Indian farmers cultivate land holdings under 2 hectares. KrishiVaani offers regional language support (Hindi, Odia, Marathi, Telugu) and speech synthesis to democratize access regardless of digital literacy.

Intelligence Layer
Multimodal AI/ML Architecture

Combines supervised classification (XGBoost/RandomForest) for crop choice, polynomial regression for harvest yield, PyTorch/CNN for leaf pathology, and vector-indexed RAG for real-time agronomic counseling.

System Topology
Decoupled Microservices

Employs an asynchronous Node.js Express API Gateway for orchestrating requests, a high-throughput Python FastAPI microservice for ML/CV inference, and MongoDB Atlas for distributed document state management.

02

Problem Statement

Indian agriculture contributes nearly 18% to the national GDP and sustains more than 50% of the workforce, yet productivity per hectare lags significantly behind global benchmarks. The agricultural community suffers from fragmented advisories, lack of localized soil testing, and delayed responses to crop distress. KrishiVaani targets seven foundational challenges:

1. Suboptimal Crop Selection

Farmers frequently plant traditional monocultures without analyzing macro/micronutrients (Nitrogen, Phosphorus, Potassium), soil pH, and seasonal precipitation, causing chronic yield depletion and soil nutrient exhaustion.

2. Information Asymmetry & Generic Advice

Broadcast advisories over radio and television lack farm-specific granularity. Farmers lack access to personalized agronomic recommendations calibrated to their exact soil profile and microclimate.

3. Misdiagnosed Plant Pathology

Fungal blights, viral mosaics, and pest infestations are misidentified or identified too late. Farmers overuse toxic broad-spectrum chemicals, inflating operational costs and poisoning soil microbiomes.

4. Yield & Harvest Uncertainty

Absence of scientific yield estimation prevents farmers from securing optimal crop insurance, forward contracts, storage logistics, and accurate credit appraisals from financial institutions.

5. Unpredictable Climate Volatility

Erratic monsoon cycles and sudden heat waves destroy unshielded crops. Farmers require localized meteorological telemetry tied directly to sowing, irrigation, and pesticide spray advisories.

6. Regional Linguistic Barriers

Over 70% of digital agricultural portals operate exclusively in formal English or Hindi, alienating millions of farmers who communicate primarily in regional dialects and prefer voice over text input.

7. Unbudgeted Production Overheads

Farmers rarely budget input expenses (seeds, fertilizers, labor, irrigation, diesel) against expected Mandi prices (MSP), resulting in unanticipated financial losses and severe debt cycles.

Non-Functional Requirements

The architecture guarantees robust enterprise performance, strict data privacy, and graceful degradation even under harsh rural connectivity conditions:

1. Scalability Horizontal

Stateless Node.js gateway and FastAPI microservices designed for horizontal autoscaling behind reverse proxies. Supports concurrent spikes up to 5,000 active farmer sessions during sowing seasons without performance degradation.

2. Availability 99.9% SLA

Multi-region deployment across redundant cloud zones with automated health checks, container restarts, and circuit breakers preventing cascading service failures.

3. Latency & Performance < 1.5s p95

ML inference latency under 250ms for tabular models (XGBoost); under 800ms for CNN leaf disease classification; RAG response generation under 2.5s with streaming chunks enabled.

4. Security & Compliance Zero-Trust

Enforces HTTPS/TLS 1.3 encryption in transit, bcrypt (cost factor 12) password hashing, short-lived signed JWT bearer tokens, CORS origin restrictions, and strict input schema sanitization.

5. Fault Tolerance Graceful Fallback

External API timeouts (Weather, Sarvam, LLM) gracefully degrade to cached telemetry, offline agronomy heuristics, or fallback browser speech synthesis with zero white-screen errors.

6. Data Privacy DPDP Act Compliant

Strict adherence to India’s Digital Personal Data Protection (DPDP) Act 2023. Farmer coordinates, mobile numbers, and land ownership records are encrypted at rest using AES-256 in MongoDB Atlas.

7. Maintainability Modular Clean Arch

Clear separation of concerns into repository, service, and routing layers. Centralized environment configuration with Pydantic settings and automated linting/formatting pipelines.

8. Observability Full Tracing

Structured JSON application logs with correlation IDs, Prometheus metrics tracking inference throughput and error rates, and Sentry integration for real-time unhandled exception telemetry.

9. Reliability Idempotent

Transactional state updates where required, automated database connection pool management, and retry policies with exponential backoff on transient third-party failures.

10. Extensibility Open Integration

Plugin architecture designed to integrate future telemetry sources including Sentinel-2 NDVI satellite bands, IoT soil moisture probes, and Agmarknet Mandi wholesale price feeds without schema redesign.

Authentication & Authorization

KrishiVaani adopts a stateless, token-based authentication mechanism designed to scale horizontally across serverless and containerized instances:

Password Hashing & Salting

Farmer passwords are salted and hashed using bcrypt with an adaptive work factor (12 rounds), guarding against offline rainbow table and dictionary attacks.

JSON Web Tokens (JWT)

Issued upon successful verification with an HMAC-SHA256 signature using a rotating secret key. Tokens carry non-sensitive claims (user_id, role) with an 8-hour expiry.

Role-Based Access Control (RBAC)

Enforces route-level authorization guards distinguishing standard farmer users from agronomist and admin roles who hold permissions to update RAG vector stores.

Stateless Request Guards

Protected endpoints utilize Express middleware extracting the Authorization: Bearer <token> header. Expired or forged tokens trigger immediate 401 Unauthorized responses.

Machine Learning Architecture

KrishiVaani's predictive intelligence leverages two supervised tabular engines and a deep convolutional neural network, hosted within the Python FastAPI microservice:

1. Crop Recommendation Engine

Algorithm: Optimized XGBoost / Random Forest Classifier trained on 2,200+ multi-regional agricultural data points (NPK, pH, temperature, humidity, rainfall).
Performance: 94.2% test accuracy across 22 Indian crop varieties (Rice, Maize, Jute, Cotton, Chickpea, etc.). Serialized via joblib.
Inference: Evaluates incoming soil metrics against calibrated decision boundaries and outputs top 3 crop probabilities with agronomic soil notes.

2. Crop Yield Forecasting Engine

Algorithm: Multi-variate Ridge & Gradient Boosted Regressor trained on 10+ years of district-level ICAR harvest records.
Input Features: Crop name, State, Agricultural season, Cultivated area (acres), precipitation, and regional soil NPK profile.
Evaluation: R² = 0.88, Mean Absolute Error (MAE) under 1.8 quintals/acre. Outputs total expected harvest and projected revenue based on current MSP.

3. Plant Pathology CNN Classifier

Algorithm: Transfer learning on MobileNetV2 / ResNet-50 pre-trained on ImageNet and fine-tuned on 54,000+ PlantVillage and indigenous crop pathology images.
Preprocessing: Resize to 224x224 RGB, random horizontal flip, and tensor normalization ([0.485, 0.456, 0.406]).
Inference: Softmax output layer classifies 15+ crop disease classes with confidence thresholding (>75% required for automated diagnosis).

Model Serving & Lifecycle Architecture

Models reside in a version-controlled model registry (/models/v2/...). At startup, FastAPI loads model artifacts into memory, executes a zero-tensor warmup pass, and exposes thread-safe asynchronous inference methods to handle high concurrent load with sub-second response times.

Retrieval-Augmented Generation (RAG) Architecture

The KrishiMitra conversational assistant employs an advanced RAG pipeline to ground LLM responses in peer-reviewed agronomic literature from the Indian Council of Agricultural Research (ICAR) and Krishi Vigyan Kendras (KVK).

1. Ingestion & Document Chunking

Agronomic handbooks, disease management compendiums, and fertilizer schedules are cleaned and split into semantic chunks of 500 tokens with 50-token overlap using recursive character text splitting to maintain contextual continuity across paragraph breaks.

2. Dense Vector Embeddings

Text chunks are transformed into dense vector representations using text embedding models (768/1536 dimensions). Vectors capture nuanced agricultural semantics such as symptoms, fungal pathogens, and regional crop seasons.

3. FAISS Vector Indexing

Vectors are indexed in a high-speed in-memory FAISS (Facebook AI Similarity Search) index using Inner Product (Cosine Similarity) metrics. Performs sub-millisecond nearest-neighbor search across thousands of agronomic passages.

4. Top-K Semantic Retrieval

Incoming user queries are vectorized and compared against the FAISS index to retrieve the top 3 most relevant document citations, filtered by regional relevance and crop classification.

5. Grounded Prompt Construction

Retrieved excerpts are injected into the system prompt alongside the farmer's registered profile (soil type, district, land size) and live weather telemetry, strictly bounded by system delimiters.

6. Hallucination Mitigation & Guardrails

The LLM is governed by strict rules: if retrieved context does not cover the question, it explicitly states uncertainty; it never invents pesticide dosages; and it strictly refuses off-topic non-agricultural queries.

Scalability Framework

The platform scales seamlessly to handle regional spikes during peak planting and monsoon advisories:

Stateless Gateway Architecture

The Node.js and FastAPI services maintain no local session state. User sessions are verified via self-contained cryptographically signed JWTs, allowing instances to scale horizontally behind round-robin load balancers.

Decoupled Heavy Compute

Machine Learning and Computer Vision inference are decoupled from the Node.js API Gateway. Heavy PyTorch tensor calculations execute on isolated Python worker containers, preventing event-loop blocking on the main server.

Multi-Layer Caching

District-level meteorological forecasts and Mandi commodity benchmarks are cached in memory and MongoDB TTL collections with a 6-to-12-hour expiration, eliminating 80% of redundant third-party API calls.

Vector Index Optimization

The FAISS vector index operates fully in RAM with quantized index options (IVF-Flat), enabling sub-50ms nearest-neighbor lookups across 100,000+ agronomic document embeddings with minimal RAM overhead.

Monitoring & Observability

Full-stack telemetry and proactive alerting maintain high operational visibility across distributed services:

Structured JSON Logging

Node.js and FastAPI log structured JSON events via Winston and Python standard logging. Every request receives a unique x-correlation-id propagating across gateway and ML microservices.

APM & Latency Tracking

Tracks p50, p95, and p99 latency metrics across API Gateway routes. Alerts trigger automatically if ML inference exceeds 1.5 seconds or LLM token streaming stalls.

Real-Time Error Alerting (Sentry)

Sentry captures unhandled backend exceptions, frontend runtime errors, and third-party API rejection rates, deduplicating crash reports with full stack traces.

ML Model Drift & Health

Logs prediction distribution vectors and confidence percentiles. Discrepancies in disease classification confidence or unusual crop output skews trigger agronomic data audits.
